explain-as-webpage：把看不懂的東西做成一頁知識網頁

結論

本儲存庫提供一個代理技能（skill）explain-as-webpage：使用者給它一個專案、一份文件或一個主題，再加上想問的問題，代理就依 SKILL.md 的 7 個步驟，產出一個單檔、離線可開的 Read the Docs 風格 HTML 網頁。流程中只有第 4 步需要使用者：代理一次列出疑問、呈現層級與輸出路徑，使用者回答後才動工。規則拆成 1 個主檔與 5 個參考檔，每次對話常駐的只有描述（估計約 400 tokens），呼叫時再載入主檔（估計約 3.7k tokens），其餘參考檔在需要的步驟才讀。

這個 skill 解決什麼問題？產出長什麼樣子？

它解決的是「代理做完了，我卻看不懂」：代理寫了一個套件、用了一個演算法，或留下一份很長的分析報告，使用者需要判斷或修改它，卻找不到其中的因果。靈感來自 Andrej Karpathy 的一則貼文（README.md 附有截圖）。第三輪（v3）把範圍從專案延伸到文件與主題：沒有軟體專案，也能把一篇文章、一份 PDF 或一個主題做成同樣好讀的網頁。

形式每頁一個 .html 檔，外觀仿 Read the Docs（sphinx_rtd_theme）；沒有建置步驟，也沒有額外的圖片或腳本資料夾
離線所有圖都是內嵌 SVG，CSS 與腳本都寫在檔內，不載入任何外部資源
結構先給結論，再以一條主軸串起全頁；每個 h2 就是讀者會問的一個問題
篇幅約 15 分鐘讀完：正文至多約 1,800 個英文字或 3,500 個中文字
語言英文或繁體中文；沒有指定時，跟隨使用者提問的語言
模板assets/template.html（254 行）內含側欄目錄、可選的頁面樹，以及通用的 stepper 元件

來源：README.md § Inspiration、§ What it produces；docs/specs/explain-as-webpage-v3.md §0；references/writing-rules.md § Length budget；CLAUDE.md § 架構

材料不同時，讀法與引用方式有什麼不同？

第 1 步依使用者給的東西分成三種模式，模式決定怎麼讀、事實怎麼標出處，以及預設輸出到哪裡。

模式使用者給的東西怎麼讀事實的出處寫法
project儲存庫、報告、程式路徑直接讀檔案檔案路徑＋段落標題或行號
document網頁文章、PDF、Markdown、貼上的文字用 curl 或 pdftotext 取得全文原文的標題或頁碼
topic只有主題與疑問先找原始文件，再搜尋補充來源＋存取日期＋等級

來源：SKILL.md § 1；references/sources-and-research.md §1

document 模式最重要的規則是「全文，不是摘要」。下表是 T1 對同樣兩篇文章的實測：WebFetch 這類透過模型回答的工具，給的是模型的摘要；curl 加上本機去除 HTML 標籤，拿到的才是原文。

材料WebFetchcurl＋去除標籤
Paul Graham〈How to Do Great Work〉要求逐字回傳時，以著作權為由拒絕，只給摘要與短引文全文 11,738 字，結尾是致謝段落
Karpathy〈LLM Wiki〉gist9 個標題正確，但各節字數是估計，加總約 2,170 字全文 1,921 字，結尾與原文一致

來源：tasks/plan.md §「T1（2026-10-03，Claude Code）」第 1 點

topic 模式由使用者選查證深度：輕量約 5–10 個來源；深度則每個關鍵主張至少兩個獨立來源，來源之間不一致時頁面要寫出來。每個來源標上等級與存取日期：g1 原始材料（論文、官方文件）、g2 權威或同儕審查（政府機關、學會）、g3 二手整理（新聞、百科）、g4 新興或個人說法；只有 g4 支持的主張要放進「新興說法」框，並寫明是誰說的。Starship 頁就是這樣：SpaceX 試飛報告是 g1，NASA 的頁面是 g2，Wikipedia 是 g3，Musk 對成本的推測放在新興說法框。健康、安全、法律、理財屬於高風險主題，只能用 g1–g2 來源，台灣讀者優先採用台灣機關的資料，頁面還要加上「注意」框，而且不提供劑量或個人建議。

來源：references/sources-and-research.md §7、§8、§9；examples/starship-reusability/starship-reusability.html § 來源

它怎麼決定頁面長相？

頁面長相由兩個獨立的選擇決定：頁型決定圖 1（全頁的主軸）與章節骨架，層級決定互動程度。頁型在第 2 步依材料的性質選：

頁型材料是圖 1（主軸）
機制（預設）技術、演算法、物理或生物機制因果鏈
套件或架構一個程式套件：做什麼、為什麼這樣設計一次工作流經各模組的主流程
程式導讀單一檔案或模組，通常是子頁主要函式的呼叫流程
論證文章、評論、一種思考方式論證圖
路線圖或計畫有階段、任務與檢查點的計畫階段路線圖；預設做成頁面樹
實務指南如何準備或決定某件事決策樹或分組清單
演進經過幾個具名階段演變的概念階段演進圖

來源：references/page-types.md 開頭的頁型表

層級在第 3 步選，原則是「能回答所有疑問的最低層級」，而且逐題決定（圖 2）：只有關於過程的那一題用動畫，其餘仍是靜態圖。本頁就是套件頁型、L0：圖 1 是請求流經各步驟的主流程，沒有一題需要互動。

來源：SKILL.md § 3 與 Red Flags；本頁與 Starship 頁的選擇見 tasks/plan.md §「T15 結果」

哪個檔案在什麼時候被讀？為什麼這樣拆？

代理平台只把每個 skill 的描述（SKILL.md 開頭的 description）常駐在每次對話裡，本體要等 skill 被呼叫才載入。因此規則越長，每次呼叫的成本越高。本儲存庫的做法是 SKILL.md 只放流程與判準（維持約 130 行以內），細節拆進參考檔，到需要的步驟才讀（圖 3）。

單位選 token：本節問的是載入成本，而模型的上下文與費用以 token 計，檔案大小只是代理指標。來源：claude --plugin-dir . plugin details sphinx-style-notes-maker 的估計值（常駐約 403 tokens、呼叫時約 3.7k tokens）。參考檔與模板的數字，是把每個檔案各包成一個測試用 skill（只加 3 行 frontmatter），再以同一個指令估得。讀取時機見 SKILL.md 第 1、2、4、5 步與 § Process 開頭。

用估計值算一次：專案模式的首次產出會讀 SKILL.md、page-types.md、writing-rules.md、svg-recipes.md 與模板，3.7k＋3.2k＋3.7k＋6.4k＋6.2k ≈ 23.2k tokens；文件或主題模式多讀 sources-and-research.md，約 28.9k tokens；全部檔案約 31.8k tokens。檔案大小不能代替 token 數：writing-rules.md 只有 9.8 KB，估計值卻和 11.8 KB 的 SKILL.md 一樣約 3.7k，因為各檔案中文與程式碼的比例不同。CLAUDE.md 也明文規定：修改規則時 SKILL.md 維持約 130 行以內，細節放進參考檔。

來源：圖 3 的估計值（加總為本頁計算）；檔案大小以 wc -c 量測；CLAUDE.md §「架構」最後一段

推論

這個拆法的代價是規則分散在 6 個檔案，彼此以章節編號互相引用（例如 sources-and-research.md §7），所以修改一個檔案的章節時，要一起檢查引用它的檔案。

追問時，頁面怎麼延伸成頁面樹？

使用者對已有的頁面追問時，代理先讀 extending-pages.md，判斷每個新問題放在哪裡（圖 4）。原則是每一頁都守住自己的篇幅預算，主頁不會越長越大。

來源：references/extending-pages.md §2

子頁一次回答 3–5 個相關問題，不是一題一頁；一個主題超過約 6 個子頁時，代理會建議另開新主題。每一頁的側欄都放同一份頁面樹，並標出目前所在的頁。第 6 步另外用三個指令確認頁面樹在各頁一致、每頁都標了自己、所有連結的檔案都存在。本儲存庫的 examples/autoresearch/ 就是這樣長出來的：主頁之後，兩個程式導讀子頁 autoresearch--train-py.html 與 autoresearch--prepare-py.html 都是以追問加入。長篇文件或計畫則可以在第一次產出時就建好頁面樹，每個階段一個子頁（§6）。

來源：references/extending-pages.md §2、§4、§5、§6；README.md § Examples

現況與限制

  • 第三輪的材料模式已在 Claude Code 以 8 個案例驗證（tasks/todo.md 第 1–4 階段）；在 Codex 上的實測（T16）尚未進行，plugin manifest 的版本仍是 0.2.0。
  • 不做影片：最高層級是瀏覽器內的逐步動畫。影片網址也不接受，因為代理無法觀看影片。
  • 需要登入的頁面（例如 X 的貼文）要靠讀取網頁的輔助 skill，或請使用者存成 PDF。
  • 圖 3 的 token 數都是 claude plugin details 的估計值，可能與實際用量不同；參考檔的估計值包含測試用 skill 多出的 3 行 frontmatter。

來源：tasks/todo.md；.claude-plugin/plugin.json；SKILL.md § When to Use；references/sources-and-research.md §1、§2

名詞

名詞在本頁的意思
skill（技能）一組給代理的指示與附檔；平台常駐它的描述，呼叫時才載入本體
plugin、manifest打包 skill 以便安裝的方式；manifest 是描述名稱與版本的 JSON 檔
descriptionSKILL.md 開頭的觸發描述，決定代理何時想到這個 skill
材料模式（project／document／topic）依使用者給的是專案、文件或只有主題，決定讀法與引用方式
頁型（page type）依材料性質決定的頁面骨架與圖 1 的形狀
層級（tier，L0／L1／L2）頁面的互動程度：靜態圖、加一個滑桿、加上逐步動畫
stepper多格的 SVG 動畫，以上一步、下一步、播放鍵逐格呈現
頁面樹（page tree）一個主頁（hub）加上連結的子頁，所有頁的側欄列出同一份清單
來源等級（g1–g4）topic 模式中標在每個來源上的可信度分級
WebFetchClaude Code 讀網頁的工具，回傳的是模型摘要而不是全文
