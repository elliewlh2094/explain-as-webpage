explain-as-webpage: a skill that turns your project into explainer pages

Conclusion

This repository holds one agent skill (a packaged set of instructions that an AI coding agent loads on demand). When you do not understand something an agent did in your project, the skill makes the agent explain it as a single HTML page, built from your own code, data, and reports. The page answers 3–5 of your questions in about 15 minutes of reading, and the agent asks you to confirm the questions before it builds anything. The three example pages for karpathy/autoresearch are 848–1,225 words each, inside the 1,800-word budget.

What problem does this skill solve?

Agents now write long reports, and long reports are hard to judge. Figure 1 shows the chain this skill was built to break. The author's own robotics project had agent-written Markdown reports of 833–1,674 lines. One of them already had matplotlib figures, and it was still hard to follow.

The design notes name four problems: the reports were too long, the text was too dense, there was no causal thread, and the figures were far from the text that explained them. Adding figures did not help, because figures were never the missing part. So the skill controls the structure of the page. It opens with the conclusion, draws one causal chain, gives each question its own section, and puts each figure next to the paragraph that explains it.

What does the agent do when you ask for a page?

It follows seven steps, shown in Figure 2. The orange step is a gate: the agent stops and waits for your answer. The green step is a self-check that loops back until every check passes.

Step 4 sends one message with four items: the core questions, the proposed tier with a cheaper alternative, the output path, and the page language. The default path is ~/Documents/explainers/<repo-name>/<topic>.html, outside your project. Step 6 runs real commands. grep confirms that no template placeholder and no external URL is left. Then a headless Chrome takes screenshots at 1280 px and 390 px wide, and the agent looks at them for overlapping labels, overflowing text, and arrows that miss their boxes.

Source: skills/explain-as-webpage/SKILL.md “Process”, steps 1–7.

How does it pick L0, L1, or L2?

By the type of each question, as in Figure 3. The agent picks the lowest tier that answers every question, and it raises the tier only for the question that needs it. The rest of the page stays at L0.

The live examples are on the autoresearch page: a static flow figure (L0), a time-budget slider (L1), and an eight-step experiment loop (L2). That page mixes all three tiers. This page uses only L0, because each of its questions is about structure or order.

The rule exists because each tier costs more to build: about 1× for L0, 1.5× for L1, and 2–3× for L2. Animation helps only when the question is about a process; for structure, a static figure is faster to read.

Source: SKILL.md step 3 (tier table, relative cost) and “Common Rationalizations”; examples/autoresearch/autoresearch.html.

What is in the repository, and when is each file read?

The skill is one folder, read in three layers, as in Figure 4. Only a short description is always in the agent's context. The rest loads when the skill runs, and the detailed rules load only at the step that needs them.

How do I install and use it?

Install it as a plugin. In Claude Code:

claude plugin marketplace add elliewlh2094/sphinx-style-notes-maker
claude plugin install sphinx-style-notes-maker@sphinx-style-notes-maker

In Codex, use codex plugin marketplace add with the same repository, then codex plugin add sphinx-style-notes-maker@sphinx-style-notes-maker. You can also copy skills/explain-as-webpage into ~/.claude/skills/ or ~/.codex/skills/. Start a new session after you install it.

Then ask in plain words, in English or Traditional Chinese. Name the code or the report the page should use:

What does the src/swarm_experiment package do, and why is it built this way?
Explain it as a web page.

Answer the step-4 message, wait for the report, and open the file with xdg-open <path> (Linux) or open <path> (macOS).

To learn more about the same topic, ask a follow-up question about the page. Figure 5 shows where the answer goes. A short answer to an existing question goes into a collapsible block on that page. A new question gets a child page that links to and from the hub page.

The autoresearch example grew this way: its train.py and prepare.py pages were added as follow-up questions, and the hub page grew by about 60 words.

Source: README.md “Installation” and “Usage”; references/extending-pages.md §1–§4; examples/autoresearch/.

What does it not do?

  • No video: the highest tier is an in-browser stepper.
  • No external libraries such as MathJax, D3, or Mermaid: formulas use HTML superscripts and subscripts.
  • No index across topics: a page tree stays inside one topic.
