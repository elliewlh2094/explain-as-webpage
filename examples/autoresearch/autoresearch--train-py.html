train.py: the one file the agent edits

Conclusion

train.py builds a small GPT model (the transformer type that predicts the next token), trains it for 300 s of training time, and prints val_bpb. It is written to be easy for an agent to change. All settings are plain constants at lines 432–451, one constant (DEPTH) sets the model size, and the learning-rate schedule follows the clock, so no change breaks the 5-minute ending. In the upstream run, every kept change gives a new value to something that already exists, such as a learning rate or a window size.

This page assumes the experiment loop from the main page: the agent edits this file, runs it, and keeps the edit only if val_bpb goes down.

What happens in one run of train.py?

Figure 1 shows the order of one run, with line numbers. Startup (the top row) does not count toward the 5 minutes. The clock runs only inside the training loop, and it skips the first 10 steps, so compilation time is free.

At import time, the file also loads FlashAttention 3, a fast GPU implementation of attention. It picks a build made for H100-class GPUs, or a generic build on other GPUs (lines 20–24). The table lists the parts that the rest of this page discusses.

How does one knob, DEPTH, set the whole model size?

DEPTH sets the number of transformer layers, and the width follows from it. The width (model_dim) is the length of the vector that represents each token. build_model_config computes it in lines 470–472:

# train.py lines 469–477
def build_model_config(depth):
    base_dim = depth * ASPECT_RATIO
    model_dim = ((base_dim + HEAD_DIM - 1) // HEAD_DIM) * HEAD_DIM
    num_heads = model_dim // HEAD_DIM
    return GPTConfig(
        sequence_len=MAX_SEQ_LEN, vocab_size=vocab_size,
        n_layer=depth, n_head=num_heads, n_kv_head=num_heads, n_embd=model_dim,
        window_pattern=WINDOW_PATTERN,
    )

Line 471 rounds DEPTH × 64 (ASPECT_RATIO) up to a multiple of 128 (HEAD_DIM). Line 472 gives one attention head per 128 dimensions. For the default DEPTH = 8: 8 × 64 = 512, already a multiple of 128, so the model has width 512 and 4 heads.

The block matrices grow 8× from DEPTH 8 to 16, not 2×. Their size is layers × width², and both the layers and the width double. The README calls DEPTH “the primary single knob that controls model complexity” for this reason. Inside a fixed 5 minutes, a model 8× larger also trains on fewer tokens, so a larger DEPTH is not automatically better.

Why two optimizers, Muon for matrices and AdamW for the rest?

The code comment says it directly: “Muon for 2D matrix params, AdamW for others” (line 357). setup_optimizer puts each parameter into one group (lines 236–266). Figure 2 shows the groups at DEPTH = 8 and the learning rate (LR) of each group.

The AdamW learning rates are multiplied by 1/√(width / 768) (line 248). The comment says the rates were “tuned at 768 dim”. At width 512 the factor is (512 / 768)−0.5 ≈ 1.22, which is the 1.22 in Figure 2. This scaling lets a DEPTH change keep sensible AdamW rates without retuning.

General background (not stated in the repository)

Muon replaces each matrix update with an orthogonalized version, so no single direction of the matrix gets most of the step. muon_step_fused does this with a few matrix multiplications (“Polar express orthogonalization”, lines 323–336). Muon is designed for the weight matrices inside the network. The usual practice is to keep embedding tables, the output head, and scalars on AdamW.

Why is the learning-rate schedule based on time, not steps?

Because the agent changes how long one step takes. A schedule based on the clock always ends exactly when the budget ends. Line 555 computes progress as training time ÷ TIME_BUDGET, from 0 to 1. get_lr_multiplier turns progress into a factor on every learning rate:

# train.py lines 518–525
def get_lr_multiplier(progress):
    if progress < WARMUP_RATIO:
        return progress / WARMUP_RATIO if WARMUP_RATIO > 0 else 1.0
    elif progress < 1.0 - WARMDOWN_RATIO:
        return 1.0
    else:
        cooldown = (1.0 - progress) / WARMDOWN_RATIO
        return cooldown * 1.0 + (1 - cooldown) * FINAL_LR_FRAC

With the defaults (WARMUP_RATIO 0, WARMDOWN_RATIO 0.5, FINAL_LR_FRAC 0), the factor is 1.0 for the first 150 s. Line 524 then lowers it in a straight line to 0 at 300 s. The upstream example run made 953 steps. If the agent halves the batch size, a step takes about half as long and there are about twice as many steps, but the factor still reaches 0 at 300 s. Move the slider in Figure 3 to change WARMDOWN_RATIO.

Source: train.py lines 445–447, 518–525, 555; program.md example output (num_steps: 953); progress.png (kept change “warmdown 0.5→0.7”).

Weight decay follows the same progress (line 531). One schedule does not: the Muon momentum rises from 0.85 to 0.95 over the first 300 steps (line 527), so it is a warm-up at the start, not a feature of the ending.

Inference

No kept label adds a new component. Two rules in program.md push in this direction: one idea per 5-minute run, and the simplicity criterion. A new value is cheap to try and rarely crashes. The pattern does not prove that structural changes cannot win; the upstream run may simply not have tried many of them. A different program.md could ask for them.

Terms

TermMeaning on this page
GPT (generative pre-trained transformer)The model type: a stack of transformer blocks that predicts the next token.
Width (model_dim)The length of the vector that represents each token: 512 by default.
Attention headOne of the parallel parts of an attention layer; here, one per 128 width.
Learning rate (LR)How large a step the optimizer takes on each update.
WarmdownThe final part of training, where the learning rate falls to its final value.
Muon / AdamWTwo optimizers: Muon for weight matrices, AdamW for the other parameters.
Embedding tableA table with one learned vector per token id. Value embeddings are extra tables that some layers add to their attention values.
Sliding windowA layer that only looks back a fixed number of tokens. In WINDOW_PATTERN, “S” is a short window and “L” is the full context.
RoPE (rotary position embedding)The way the model encodes token positions; its base frequency sets the range of wavelengths.
FlashAttention 3A fast GPU implementation of attention, loaded at import time.
