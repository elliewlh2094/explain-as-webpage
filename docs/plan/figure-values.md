# 圖中每個數字都要說明意義

## Problem Statement

我們如何讓代理畫出的每一張含數值的圖，都能讓讀者只看圖與圖說，就答得出每個數字量的是什麼、單位、怎麼讀、從哪來？

起因：儲存庫說明頁的圖 3 以位元組數畫各檔案的長條，只有兩列標 token 數。單位混用，而且位元組數不代表載入成本：`writing-rules.md` 9.8 KB 與 `SKILL.md` 11.8 KB 的 token 估計值同為約 3.7k。第一次修正只寫了「依問題選單位」，使用者認為範圍太窄，應該涵蓋各種圖表：機器人位移用公尺、溫度用攝氏或華氏、ROC 曲線沒有單位但要說明兩軸的意義。

## Recommended Direction

在 `writing-rules.md` § Figures and text 把「選單位」規則改寫成通用的**讀圖四問**。圖中每個數字，包括座標軸、長條、滑桿，以及機制圖方框裡的單一數字，都要答得出：

1. **量的是什麼**：讀者在比較的量。
2. **單位**：寫出單位。沒有單位時，寫出定義與範圍，例如 AUC 介於 0 到 1。依問題選單位，不用只是容易量的代理指標。
3. **怎麼讀**：方向（越大越好或越小越好）、基準線、參考線的意義。
4. **從哪來**：量測、計算、估計或示意；估計值要標明。

四問分散在三處回答：軸名、單位與圖例放圖內；怎麼讀放前一段或圖說；來源放來源行。第 7 步回報時，再列出每張數值圖的單位與選用理由。

`svg-recipes.md` 新增一節「座標軸與刻度」，寫成可照做的畫法，附三個例子：機器人位移（m）、溫度（°C 或 °F，依讀者所在地區）、ROC（FPR 與 TPR，範圍 0 到 1、沒有單位，對角線代表隨機猜測，AUC 是曲線下面積）。另加**示意圖規則**：說不出數字的依據時，不放刻度，並標「示意，不按比例」。

檢查方面，`SKILL.md` 第 6 步把「每個數字都有來源」擴充為「每個數字都有來源、單位與意義」，行數不變；「只顯示圖」的截圖改為同時保留圖說與來源行。另外，把放在 English 小節、只約束英文頁的「Give every number its unit」移到適用所有語言的位置。

## MVP Scope

- `writing-rules.md`：讀圖四問取代「選單位」規則；「每個數字給單位」移到適用所有語言的位置。
- `svg-recipes.md`：座標軸與刻度一節（三個例子）、示意圖規則、截圖 CSS 保留圖說與來源行。
- `SKILL.md`：第 6 步清單合併一項；第 7 步回報已有的單位說明維持。
- 驗收：儲存庫內四個範例（autoresearch、explain-as-webpage、llm-wiki、starship-reusability）的所有數值圖，依四問檢查並修正。

## Not Doing (and Why)

- **依讀者換算成生活量感** —— `writing-rules.md` § Reader 已要求一般大眾頁用日常語言；換算本身也容易出錯。
- **自動檢查腳本** —— 數字是否需要單位要看語境，腳本會大量誤報，人工檢查較可靠。
- **每張圖下方固定一個「怎麼讀」表格** —— 使用者選擇分散在圖內、圖說與來源行回答；固定區塊會增加篇幅。
- **翻修所有本機舊頁面** —— 只修正儲存庫內的範例；本機產物等使用者需要時再處理。
