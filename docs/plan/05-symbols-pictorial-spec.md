## 1. 需求

### R1 符號對照圖

現有的 `writing-rules.md` § Ground the symbols in one running example 要求一張「符號 → 例子中的意義」對照表。R1 把符號放進圖裡，並讓公式與圖使用相同的顏色。

1. **圖說明單新增「Symbols」欄**（`explainer-figure/SKILL.md` § Figure brief）：每一列寫出符號、它在圖上對應的部位、它的概念色；圖上沒有公式符號時寫「none」。
2. **圖上標出符號**：符號放在對應部位旁，後面接一般文字，例如「x̂ₖ 估計位置」。有 Unicode 下標字時直接使用（ₖ、ₜ、ᵢ、₀–₉）；沒有對應字元時，在符號內巢狀 `<tspan baseline-shift="sub" font-size="12">`（2026-10-13 T5 修改：原寫法的 `class="sm"` 會把下標改成灰色，取代概念色）。符號標籤使用 14px，因為 12px 時 Unicode 下標只剩約 7px。
3. **公式中的符號上色**：模板目前只為 SVG 文字、`.chip` 與 `.card` 定義概念色，HTML 段落中的文字沒有。新增一個 HTML class，暫定寫法為 `<span class="sym c2">P<sub>k</sub></span>`，CSS 為 `.sym { color: var(--cc) }`。實際的 class 名稱在實作時確定。
4. **上色的範圍**：只有關鍵概念的符號使用概念色，所以一頁最多 5 個符號上色，與 `SKILL.md` 第 2 步「關鍵概念最多 5 個」一致。其餘符號仍在圖上標出，也列在符號對照表中，但用一般文字色。
5. **同一個符號在整頁使用同一個顏色**：公式、圖、對照表三處一致。
6. **引用**：`writing-rules.md` § Ground the symbols 加一行，指向 explainer-figure 的符號規則。規則本身寫在 explainer-figure。
7. **對比**：`.sym` 的文字色就是 `c1`–`c5`。既有的對比檢查已涵蓋這 5 個顏色，不需要新增檢查項目，只需確認 `.sym` 沒有使用其他顏色。

### R2 壓線檢查

1. **檔案**：新增 `skills/explainer-figure/scripts/check-overlap.js`，執行時不需要網路。
2. **執行方式**：把頁面複製成暫存檔，在 `</body>` 前插入這支腳本，以 headless Chrome 開啟，再用 `--dump-dom` 讀出報告。`SKILL.md` § Self-check 只放一段執行指令。
3. **檢查範圍**：頁面中每一個 `<figure>` 的 SVG。stepper 要逐幀檢查，只檢查該幀可見的元素。
4. **檢查項目**：

| 類別 | 內容 | 例子（第 4 輪記錄的缺陷） |
|---|---|---|
| 1 文字重疊 | 兩個文字框重疊 | — |
| 2 線條穿過文字 | 有外框線的元素（`line`、`path`、`polyline`，以及 `rect`、`circle`、`ellipse` 的邊）穿過文字框。以 `getTotalLength` 與 `getPointAtLength` 沿線取樣 | 虛線箭頭穿過標籤；拖曳箭頭穿過檔名；箭頭穿過欄位名；註解與引線重疊；「側袋」標籤壓到包身 |
| 3 文字跨在填色邊界上 | 文字框一部分在填色形狀內、一部分在外。以 `isPointInFill` 判斷 | `sm` 標籤壓到長條左緣 |

5. **排除**：
   - 元素（或它的祖先）加上 `data-touch` 屬性時，不參與類別 2、3 的檢查。這個屬性用在本來就應接觸文字的線，例如指到文字的引線端點。
   - 內容相同、位置相差小於 1px 的兩個文字視為後續幀的重畫，不算類別 1。
6. **`<use>` 的處理**：`<use>` 引用的形狀在 shadow tree 中，無法逐一取得。類別 3 改用 `document.elementsFromPoint` 對文字框上的取樣點做點擊測試，不用 `<use>` 的外框（旋轉後的外框比物件大，會誤報）。
7. **輸出**：每個問題一行，格式為 `fig-N [frame k] 類別: "文字內容" × 元素描述`。全部通過時不印出任何內容，與其他自檢指令一致。
8. **不檢查**：語意錯誤（例如箭頭指錯對象）、間距過小但沒有重疊（例如兩條註解太近）、線穿過物件、物件疊在物件上。這些仍靠截圖判讀。

### R3 插圖風格規範、零件函式庫與姿態

1. **一種風格：粗外框＋平塗色**。這份規範寫在 `pictorial.md`，適用於任何圖中的自繪物件（R6）。
   - 外框：線寬 4px，圓角的線端與轉角，顏色為 `--text`。
   - 填色：只使用模板變數，包括 `--*-bg` 淺底與概念色淺底 `--cb`；深色部件（輪子、引擎噴嘴）用 `--text`，玻璃（車窗、感測器）用 `--blue-bg`。不使用漸層。
   - 陰影：最多一層。做法是把主體形狀再畫一次，以 `--cc` 低不透明度填色，並以圖自己 `<defs>` 中的 `clipPath` 裁到背光側。
   - 由多個形狀組成、需要單一外輪廓的物件（人體）：先畫兩倍線寬的外框層，再蓋上無外框的填色層。分開的部件之間至少相距兩倍線寬加 3px，否則外框會把它們黏在一起。
   - 模板新增的風格 class 不加 `svg ` 前綴。原因：`<use>` 引用的內容在 shadow tree 中，`svg .x` 這類後代選擇器不會套用（T2 實測，物件全部變黑）。P5 物件的定義中不使用 `box`、`line` 等既有 class。
   - 變化（例如填色深淺）以 CSS 自訂屬性傳遞，並與概念色 class 放在同一個元素上。
   - 物件不使用 `scale()`，直接畫成需要的大小。原因：`scale()` 會讓外框變細，而 `vector-effect` 不會繼承進 `<use>`。零件函式庫依尺寸參數輸出幾何，直接滿足這一點。
2. **零件函式庫** `skills/explainer-figure/scripts/parts.py`：
   - 只使用 Python 3 標準函式庫，執行時不需要網路。
   - 以命令列子指令把 SVG 片段印到 stdout。參數包含位置、尺寸、角度、id 前綴與概念色 class。函式依尺寸直接輸出幾何，不使用 `scale()`。
   - **基本形**：組合物件與示範需要的形狀，例如藥丸形、只有部分圓角的矩形、圓柱、以兩層畫法取得單一外輪廓的形狀聯集。實際清單在實作時確定。
   - **組合物件**：
     - 人體：全身高等於 5 個頭徑；軀幹只有肩膀兩角是圓角，下緣是直角；腿的上緣平直並伸進軀幹，只有下端是半圓，這樣軀幹與腿之間不會出現兩段圓弧相交的缺口；雙腿的外緣與軀幹兩側切齊，交接處沒有段差（2026-10-13 檢查點 B）；手臂是藥丸形，自肩點向外傾斜 25°；只留整體的單一外輪廓（第 1 點）。
     - 機器人：常見的輪式機器人，不限定俯視。視角參數在實作時確定；T6 需要在平面上表示朝向。
     - 無人機：四旋翼。
   - **不做火箭函式**：特定實物（例如 Starship）依 R6 第 4 點，以代理查得的資料畫出辨識特徵。
   - **背包與車**：在 `pictorial.md` 中示範如何以基本形組合，不另寫函式。
   - **零件總覽圖**：一個子指令輸出所有基本形與組合物件，供 V3 檢查與 R7 並排比較。
3. **新配方 P5「物件與姿態」**：
   - 物件只定義一次，放在圖自己的 `<defs>` 中，id 以圖號開頭（例如 `f4-booster`），並且朝向 +x 方向。
   - 每個姿態用 `<use href="#f4-booster" transform="translate(x y) rotate(θ)">` 擺放。
   - 搭配 stepper：每一幀只顯示當下的姿態，不顯示先前的姿態。軌跡以淡色虛線隨步驟累積：第 k 步加上從第 k−1 個姿態到第 k 個姿態的那一段（`data-step="k+"`），還沒走到的路徑不顯示。讀者看得出物件從哪裡來，不會被之後的路徑干擾（2026-10-13 檢查點 C 修改；原為整條軌跡常駐）。
   - 姿態的座標從軌跡算出，物件要落在軌跡線上。由零件函式庫的姿態子指令依軌跡計算每一步的位置與角度，輸出 `<use>` 與每一步的軌跡段；物件在 stepper 中途才出現時（例如分離後的助推器），以參數指定第一個姿態的步數。
   - 姿態變化大的段落（例如轉向超過 90°）拆成中間步驟。每個 stepper 仍不超過 8 步（`writing-rules.md` § Length budget）。
   - 多個物件組合後再分離時（例如飛船與助推器），分離前把兩個物件放在同一個 `<g transform>` 中，分離後各自擺放。
4. **既有規則維持**：`pictorial.md` 的「物件要自己畫，不用圖示；圖示只標部件」不變；R6 擴大物件的使用範圍，不改變這條規則。外形複雜的有機物件（胃、大陸輪廓）仍不以手寫座標描繪，改用簡單形狀的示意或留給 explainer-cite。
5. **既有配方 P1–P4 改用同一種風格**（2026-10-13 檢查點 C 新增）：第 1 點的風格適用於任何圖中的物件，所以 P1–P4 的物件外框與部件也改用 `ink` 系列，不再使用 2px 的 `outline` 與 `box` 部件。T18 確定的寫法：分層畫成 `ink cN` 矩形，剛好蓋住容器的外接框並裁切到容器形狀內，最後以只有外框的 `ink hollow` 畫容器外框；物件內的填色區域（水位）以第二份物件加上概念色與 `ink-level`，放在裁切的 `<g>` 中；模板移除不再使用的 `outline`、`edge`、`shape`、`area`。

### R6 節點外觀

1. **原則**：在所有圖型中，節點代表外形熟悉的具體東西（人、機器人、瀏覽器、資料庫、火箭）時，畫成那個東西；代表抽象概念時用方框。形狀不能提供標籤以外的資訊時（例如所有節點都是同一類東西），也用方框。圖型仍依問題選擇，節點的外觀依它代表的東西決定。
2. **判準**：遮住所有文字後，讀者仍能從形狀認出具體節點，結構仍能表達圖說明單 Message 欄中的關係（Isomorphism Test，取自 excalidraw-diagram-skill）。
3. **畫法**：
   - 物件使用 R3 的風格。有對應的組合物件時用零件函式庫，沒有時以基本形組合。
   - 物件仍保留外接框，箭頭的端點接在外接框的邊上。
   - 每個節點仍要有標籤。
4. **外形依據**：畫特定的實物時，依代理能取得的資料（官方說明、照片的描述、尺寸）畫出它的辨識特徵，不用通用外形代替。回報時列出依據與來源。資料不足時，依 `sources-and-research.md` 請使用者提供。
5. **修改的位置**：
   - `explainer-figure/SKILL.md` 圖型表後的段落：寫入第 1 點。
   - `pictorial.md` 開頭：圖型依問題選擇，節點外觀依東西決定；風格規範適用於任何圖中的物件；P1–P5 是整張具象插圖的版面配方。
   - `icons.md` 第 55 行：禁令限縮為「不要在標籤旁假造 Lucide 沒有的小圖示」；需要在節點大小被認出的東西，依 `pictorial.md` 畫成物件。
   - `svg-recipes.md` Recipe 3：具體元件畫成物件、抽象元件保留方框，並附一段可複製的片段，示範兩者並存與箭頭的端點。
6. **不做**：元件物件清單、連線使用目標元件的顏色、雙向平行箭頭（理由見〈8. 不做的事〉）。

### R7 意圖檢查

1. **先比對意圖，再找缺陷**：截圖後先對照圖說明單的 Message 欄，確認圖達到設計目的，再執行既有的缺陷檢查。修正後重新截圖，直到兩者都通過。
2. **Self-check 新增 3 項**，各附可執行的指令：
   - 遮住文字的截圖：在只看圖的截圖中隱藏圖內的 SVG 文字，依 R6 第 2 點判讀。
   - 與零件總覽圖並排：物件的線寬、填色與比例與總覽圖一致。
   - 放大截圖：以 `--force-device-scale-factor=4` 截取物件的交接處，例如關節、組合物件分離的位置。
3. **行數**：指令細節使 `explainer-figure/SKILL.md` 超過約 130 行時，移到 references。

## 6. 邊界

- **Always**
  - 維持單檔 HTML，不使用外部資源。
  - 頁面大小維持 ≤ ~150 KB。
  - 兩個 `SKILL.md` 各在約 130 行以內。
  - 四個 manifest 檔的版本號同步。
  - 新的指令寫進 skill 後實際執行一次。
  - 每個檢查點提供 `git add` 範圍與提交訊息，由使用者提交。
- **Ask first**
  - 新增第 3 節以外的 reference、腳本或資產。
  - 取代 `examples/` 中的頁面或圖。
  - 改變 L0–L2 的判準或篇幅預算。
  - 修改 `skills/explainer-page/SKILL.md`。
- **Never**
  - 產頁時從網路下載圖示。
  - 引入插圖庫，或在 Lucide 之外再引入其他圖示庫。
  - 用手寫座標描繪有機形狀（胃、大陸輪廓）。
  - 把 EKF 頁這類以第三方材料或主題查證產出的頁面加入版本控制，除非使用者決定。
  - 代替使用者 commit。

- **壓線檢查涵蓋語意錯誤與間距**：無法用幾何判斷，仍靠截圖判讀。
- **插圖庫（2026-10-10 決定）**：彩色 Noto Emoji 與「粗外框＋平塗色」風格差異太大；單色 Noto Emoji（字型版）是線稿，無法填色；Iconoir 與 Lucide 同類而覆蓋率較低；Flaticon UIcons 的授權不允許放進儲存庫再散布。詳見實作計畫〈結果〉。
- **元件物件清單、連線使用目標元件的顏色、雙向平行箭頭（2026-10-12 撤回）**：這 3 項是針對 g3 外觀的個別規則，不處理根本原因；R6 以一條原則取代。
- **火箭函式（2026-10-12 決定）**：特定實物要依資料畫出辨識特徵（R6 第 4 點），預設的火箭外形會取代這個步驟。
- **anatomy 等級的零件庫、WebGL 與 3D**：一張圖需要 30–90 分鐘與 40–80 個零件，與「選最便宜的呈現層級」衝突。詳見 `docs/plan/05-symbols-pictorial-skill-survey.md`。
- **修改 `skills/explainer-page/SKILL.md`**：它已有 130 行，本輪的需求都能放在 explainer-figure 與 references 中。
